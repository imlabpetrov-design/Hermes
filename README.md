## Важно про SSH-ключ

Ключ должен лежать **на твоём компьютере**, в `~/.ssh/id_ed25519`:
именно оттуда его читают и `ssh`, и Hermes Desktop. Эта сессия Claude
работает в одноразовом облачном контейнере — ключ, созданный здесь,
исчезнет вместе с контейнером и Hermes Desktop его не увидит. Поэтому
генерация вынесена в скрипт, который ты запускаешь у себя.

### macOS / Linux

```bash
bash setup-ssh-key.sh
```

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-ssh-key.ps1
```

Скрипт:

1. создаёт `~/.ssh/id_ed25519` (`ed25519`, 100 раундов KDF) — **существующий ключ не перезаписывает**, берёт его;
2. ставит права `700` на `~/.ssh` и `600` на приватный ключ — без этого `ssh` откажется работать;
3. добавляет ключ в `ssh-agent` (на macOS — с сохранением в Keychain, на Windows — через службу `ssh-agent`);
4. печатает только публичную часть `~/.ssh/id_ed25519.pub`.

Парольная фраза по умолчанию не ставится: иначе Hermes Desktop не сможет
открыть ключ сам, без интерактивного запроса пароля. Если фраза нужна —
убери `-N ""` из `ssh-keygen` в скрипте; ключ всё равно попадёт в `ssh-agent`,
но проверь, что Hermes Desktop умеет работать через агент.

## Когда появится сервер

```bash
# 1. вписать значения в .env
# 2. положить публичный ключ на сервер
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@SERVER_IP
# 3. проверить вход по ключу
ssh -i ~/.ssh/id_ed25519 root@SERVER_IP
# 4. после проверки — отключить вход по паролю:
#    /etc/ssh/sshd_config -> PasswordAuthentication no  && systemctl restart ssh
```

Пароль root из `.env` нужен только для первой загрузки ключа. После шага 4
он перестаёт быть входом в систему — это и есть цель.
